# AppVolumeLock

**AppVolumeLock запоминает громкость приложений из микшера Windows и возвращает её, когда Windows 11 сбрасывает ползунки на 100%.**

Один PowerShell-файл. Без установки, драйверов, служб и значка в трее — только фоновый цикл поверх Core Audio API (WASAPI).

[English version](README.md) · [Лицензия MIT](LICENSE)

## Проблема

В Windows 11 у каждого приложения своя громкость: **Параметры → Система → Звук → Громкость микшера**. Значения сохраняются, но Windows перезаписывает их на **100%** каждый раз, когда аудиосессия приложения пересоздаётся или регистрируется заново:

- приложение перезапустилось или пересоздало звуковой поток;
- вы переключили устройство вывода по умолчанию (наушники ↔ динамики);
- приложение долго молчало и снова начало играть;
- перезапустилась звуковая служба.

Понятия «это уровень, который выбрал пользователь» в Windows нет: побеждает тот, кто записал значение последним. Для программ, которые вы держите на 20–40%, это внезапный громкий звук и ползунок, который приходится тащить назад.

Править недокументированные бинарные ключи реестра, где Windows хранит эти уровни, ненадёжно и не поддерживается. Практичное решение — небольшой сторож, который реагирует на сброс.

## Что делает скрипт

AppVolumeLock — **это память микшера, а не фиксатор громкости**. Он не спорит с вами: сдвинули ползунок — новое значение становится эталоном.

| Ситуация | Поведение |
| --- | --- |
| Приложение впервые появилось в микшере | Запоминает текущий уровень как эталон |
| Вы двигаете ползунок | Сохраняет новое значение как намеренное |
| Приложение перезапустилось, сессия создалась заново | Возвращает сохранённый уровень |
| Windows поставила 100% | Возвращает сохранённый уровень, даже если звук в этот момент играл |
| Сброс случился при открытом микшере | Доводит громкость на следующем проходе |
| У приложения несколько сессий (например, Discord) | Каждый ползунок помнится отдельно |

## Как это работает

Каждые 5 секунд скрипт перечисляет аудиосессии устройства воспроизведения по умолчанию и сравнивает текущий уровень каждой сессии с сохранённым.

**Сброс или ручная правка?** Скрипт смотрит, какое окно на переднем плане:

- «Параметры» (`SystemSettings` / `ApplicationFrameHost`), старый `SndVol`, выпадающая панель (Win+A — `ShellExperienceHost` / `ShellHost`) или любое окно, в заголовке которого есть *микшер / mixer / громкость / volume* → микшер открыт, значит **любое изменение считается вашим** и сохраняется, включая намеренные 100%;
- иначе прыжок **ровно на 100%**, когда сохранённый уровень ниже, → считается **сбросом Windows** и откатывается;
- любой другой прыжок → тоже считается вашей правкой и сохраняется.

Поэтому скрипту не нужно знать, *почему* Windows сбросила уровень: открытый микшер — это сигнал, что ползунок трогает человек.

**Несколько сессий у одного приложения.** У приложения может быть несколько ползунков (у Discord отдельно голос и звуки уведомлений, причём идентификатор сессии у них одинаковый). Состояние привязано к `SessionInstanceIdentifier` **и** PID процесса, поэтому правка одного ползунка не тянет за собой второй. Правила дополнительно умеют разделять сессии по командной строке процесса-владельца.

**Хранение.** Сохранённые уровни лежат в небольшом JSON-файле и переживают перезагрузку. Именованный мьютекс не даёт запуститься второму экземпляру.

## Требования

- Windows 10 или Windows 11 (разработано и проверено на Windows 11).
- Windows PowerShell 5.1 — входит в состав Windows. PowerShell 7 не требуется, и эта конфигурация не проверялась.
- Запуск не требует прав администратора. Регистрация задачи в Планировщике может потребовать повышения прав в зависимости от политики; если не получится, `-Install` создаст ярлык в папке «Автозагрузка».
- Никаких внешних модулей, драйверов, служб и обращений в сеть.

## Быстрый старт

```powershell
git clone https://github.com/d1m40fficial/AppVolumeLock.git
cd AppVolumeLock

# Скачанные из интернета файлы Windows блокирует
Unblock-File .\AppVolumeLock.ps1

# Только чтение: показать живые сессии, сохранённые уровни, правила и ключи
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -ListSessions

# Автозапуск: задача Планировщика при входе в систему, скрытое окно
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -Install
```

Автозапуск не нужен? Запустите скрипт без параметров и оставьте окно открытым (или свёрнутым):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1
```

Первый проход запоминает то, что сейчас стоит в микшере. Выставьте нужные уровни **при открытом микшере** — они и станут эталоном.

## Командная строка

| Параметр | Описание |
| --- | --- |
| *(без параметров)* | Фоновый цикл (по умолчанию интервал 5 с) |
| `-ListSessions` | Показать все текущие аудиосессии, сохранённые уровни, подошедшее правило и ключ памяти; выйти |
| `-Once` | Один проход и выход (отладка) |
| `-IntervalSeconds <int>` | Интервал опроса в секундах; `0` — взять из `$Config` |
| `-LogFile <path>` | Путь к лог-файлу |
| `-NoLog` | Не писать лог-файл |
| `-Reset` | Забыть все сохранённые уровни (удалить файл памяти); правила не затрагиваются |
| `-Install` | Настроить автозапуск и выйти |
| `-Uninstall` | Удалить автозапуск и выйти |

Примеры:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -Once
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -IntervalSeconds 2
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -Reset
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -Uninstall
```

## Настройка

Все настройки — в блоке `$Config` в начале скрипта.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `IntervalSeconds` | `5` | Как часто проверять сессии |
| `MemoryFile` | `%LOCALAPPDATA%\AppVolumeLock\volume-memory.json` | Где хранятся сохранённые уровни |
| `Rules` | Discord, Chrome, Edge, Firefox | Исключения для отдельных приложений (см. ниже) |
| `TrackAllProcesses` | `$true` | Отслеживать все приложения со звуком; `$false` — работать только по белому списку `Rules` |
| `SilenceResetSeconds` | `20` | Устарело и игнорируется; оставлено, чтобы старые конфиги не ломались |

### Правила

Правила — это **исключения**, а не белый список. При `TrackAllProcesses = $true` (по умолчанию) приложения без правила всё равно отслеживаются под ключом, равным имени процесса в нижнем регистре. Правила применяются сверху вниз, побеждает **первое совпадение**.

Поля правила:

| Поле | Значение |
| --- | --- |
| `Name` | Понятное имя для лога |
| `Process` | Имя процесса; поддерживаются маски (`chrome`, `Discord*`) |
| `Key` | Ключ памяти; по умолчанию имя процесса в нижнем регистре. Разные `Key` — разная память для сессий одного приложения |
| `SessionIdentifier` | Regex, которому идентификатор сессии **должен** соответствовать |
| `NotSessionIdentifier` | Regex, которому идентификатор сессии **не должен** соответствовать |
| `ProcessCommandLine` | Regex по командной строке процесса-владельца — единственный надёжный способ различить сессии с одинаковыми идентификаторами |
| `NotProcessCommandLine` | Негативный regex по командной строке |
| `DisplayName` | Regex по отображаемому имени сессии |
| `NotDisplayName` | Негативный regex по отображаемому имени |
| `Ignore` | `$true` — вообще не трогать эти сессии |
| `SkipSystemSounds` | `$true` по умолчанию — системные звуки не трогать |

Примеры из комплекта:

```powershell
Rules = @(
    # У Discord два ползунка (голос / звуки уведомлений) с одинаковым
    # идентификатором сессии. Отличается командная строка процесса:
    #   --type=utility --utility-sub-type=audio.mojom.AudioService -> уведомления
    #   --type=renderer                                          -> голос
    @{ Name = 'Discord: уведомления'; Process = 'Discord'; Key = 'discord:notifications'
       ProcessCommandLine = 'utility-sub-type=audio\.mojom\.AudioService' }
    @{ Name = 'Discord: голос'; Process = 'Discord'; Key = 'discord:voice'
       NotProcessCommandLine = 'utility-sub-type=audio\.mojom\.AudioService' }

    # Браузеры плодят много звуковых процессов -> один ключ на браузер
    @{ Name = 'Chrome';  Process = 'chrome*';  Key = 'chrome' }
    @{ Name = 'Edge';    Process = 'msedge*';  Key = 'edge' }
    @{ Name = 'Firefox'; Process = 'firefox*'; Key = 'firefox' }
)
```

Перед написанием правил запустите `-ListSessions`: вывод показывает идентификатор сессии, PID, текущую и сохранённую громкость, подошедшее правило, ключ памяти и роль из командной строки (например, `utility: audio.mojom.AudioService`).

## Файлы и данные

| Путь | Назначение |
| --- | --- |
| `%LOCALAPPDATA%\AppVolumeLock\volume-memory.json` | Сохранённые уровни |
| `%LOCALAPPDATA%\AppVolumeLock\app-volume-lock.log` | Лог; при 1 МБ переименовывается в `.old` |
| Задача Планировщика `AppVolumeLock` | Автозапуск при входе (основной способ) |
| `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\AppVolumeLock.lnk` | Запасной автозапуск, если задачу зарегистрировать не удалось |

Формат файла памяти:

```json
{
  "version": 1,
  "channels": {
    "chrome": {
      "volume": 0.35,
      "process": "chrome",
      "updatedUtc": "2026-11-19T12:34:56.7890123Z"
    }
  }
}
```

`volume` — доля от `0.0` до `1.0`, как в микшере.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Громкость всё равно прыгает на 100% | Посмотрите лог: повторяющиеся сбросы означают, что приложение постоянно пересоздаёт поток. Попробуйте `-IntervalSeconds 2` и убедитесь, что запущен только один экземпляр |
| Мою правку откатили | Двигайте ползунок при открытом микшере или «Параметрах» на переднем плане — именно так скрипт понимает, что это сделал человек |
| Хочу навсегда 100% | Так же: выставьте 100% при открытом микшере, и значение запомнится как намеренное |
| Приложение не отслеживается | У него должна быть живая аудиосессия; завершённые пропускаются. Проверьте `-ListSessions` |
| Скрипт не запускается | Выполните `Unblock-File .\AppVolumeLock.ps1`; в командах выше политика выполнения уже обходится |
| Антивирус ругается на скрипт | Скрипт компилирует маленький C#-помощник **в памяти** через `Add-Type`; ничего не скачивает и не устанавливает. Весь исходник — в файле |
| У Discord оба ползунка тянут одно значение | Разделяющие правила уже в комплекте; проверьте их через `-ListSessions` |
| После смены устройства уровни другие | Windows хранит громкость микшера отдельно для каждого устройства вывода. AppVolumeLock приводит уровень к сохранённому на **текущем устройстве по умолчанию**; профили под устройства не поддерживаются |

## Удаление

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\AppVolumeLock.ps1 -Uninstall

# Необязательно: забыть сохранённые уровни и удалить логи
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\AppVolumeLock"
```

После этого удалите папку со скриптом. Службы, драйверы и ключи реестра не создаются — удаляется только задача Планировщика (или ярлык автозагрузки).

## Ограничения

- Только устройство воспроизведения по умолчанию (роль `eConsole`); сессии записи не обрабатываются.
- Опрос раз в 5 секунд; очень короткие сессии можно пропустить.
- Нет графического интерфейса и значка в трее — настройка правкой скрипта.
- Определение открытого микшера эвристическое; после изменений интерфейса Windows имена процессов может потребоваться обновить.
